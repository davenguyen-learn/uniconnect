\end{itemize}

\section{Cấu trúc thư mục dự án}

Để đảm bảo tính độc lập giữa các miền nghiệp vụ (Domain-Driven), dễ bảo trì và mở rộng khi phát triển quy mô lớn, mã nguồn của hệ thống Backend được tổ chức theo kiến trúc hướng Module (Modular Architecture). Mỗi phân hệ chức năng độc lập chứa toàn bộ mô hình dữ liệu (models), dịch vụ nghiệp vụ (services), lược đồ xác thực dữ liệu (schemas) và bộ định tuyến API (router). Cấu trúc thư mục chi tiết của dự án được tổ chức như sau:

\begin{mycode}[Project Directory Structure - Modular Architecture]{}
server/
    app/
        core/               # Core configuration, DB session & security
            config.py       # Pydantic BaseSettings environment config
            database.py     # SQLAlchemy 2.0 AsyncSession management
            security.py     # Password hashing (bcrypt) & JWT token handling
        modules/            # Domain-driven feature modules
            activities/     # Activity lifecycle, PostGIS location & conflict checks
            admin/          # System admin, organization verification & audit logs
            auth/           # Authentication, registration & user verification
            calendar/       # Smart calendar, busy timeslots & .ics export
            chat/           # AI ReAct Agent & pgvector semantic RAG
            forms/          # Polymorphic custom registration forms
            groups/         # Student groups, management & co-hosting delegation
            interactions/   # Social interactions: threaded comments & likes
            notifications/  # Real-time push notifications & event queue
            participation/  # Join requests, HMAC-SHA256 QR & GPS check-in
            reports/        # Content violation reports & moderation
            trophies/       # Gamification trophies & badge achievements
            users/          # User profiles, RBAC & follow relationships
        main.py             # FastAPI entrypoint & router aggregation
    alembic/                # Database schema migration scripts
    tests/                  # Automated test suite (94 test cases)
    Dockerfile.prod         # Production server container specification
    docker-compose.prod.yml # Multi-container orchestration (Nginx, App, DB)
    requirements.txt        # Python backend dependencies
\end{mycode}

\section{Mô tả các thành phần hệ thống}
Việc tổ chức mã nguồn theo kiến trúc module trên giúp triệt tiêu sự phụ thuộc chéo và phân tách rõ ràng trách nhiệm giữa các miền nghiệp vụ:

\begin{itemize}
    \item \textbf{Thư mục \texttt{app/core/}:} Đóng vai trò nền tảng hạ tầng, cung cấp phiên làm việc cơ sở dữ liệu bất đồng bộ (\textit{AsyncSession}), cơ chế băm mật khẩu và cấu hình tập trung.
    
    \item \textbf{Thư mục \texttt{app/modules/}:} Mỗi thư mục con là một đơn vị khép kín đảm nhiệm trọn vẹn vòng đời của một tính năng. Ví dụ: thư mục \texttt{activities/} vừa định nghĩa thực thể SQLAlchemy \texttt{Activity}, vừa kiểm soát lược đồ Pydantic và hiện thực thuật toán đối soát lịch.
    
    \item \textbf{Hệ thống \texttt{alembic/}:} Đảm nhận vai trò quản lý các phiên bản cấu trúc cơ sở dữ liệu. Mọi thay đổi trong mô hình dữ liệu đều được ghi vết và cập nhật đồng bộ vào Database thực tế thông qua các kịch bản Migration, đảm bảo tính toàn vẹn dữ liệu.
    
    \item \textbf{Docker và Containerization:} Toàn bộ hệ thống Backend và các dịch vụ bổ trợ (PostgreSQL, pgvector, PostGIS) được đóng gói trong các Container riêng biệt, giúp đồng nhất môi trường phát triển và môi trường vận hành thực tế.
\end{itemize}

\section{Hiện thực các tính năng cốt lõi}

\subsection{Xử lý dữ liệu không gian và Bản đồ (Geospatial Handling)}
Để quản lý các hoạt động trên bản đồ campus, hệ thống sử dụng tiện ích mở rộng \textit{PostGIS} của PostgreSQL kết hợp với thư viện \textit{GeoAlchemy2}. Dữ liệu tọa độ được lưu trữ dưới định dạng hình học \texttt{POINT} với hệ tọa độ \texttt{SRID 4326}.

\begin{mycode}[Geospatial Field Definition in Activity Model]{Python}
# Define geospatial Point field (latitude, longitude)
marker_location = mapped_column(
    Geography(geometry_type="POINT", srid=4326), nullable=True
)
meeting_location: Mapped[str | None] = mapped_column(String(200), nullable=True)

@property
def latitude(self):
    """Extract latitude from Geometry data"""
    if self.marker_location is not None:
        return to_shape(self.marker_location).y
    return None

@property
def longitude(self):
    """Extract longitude from Geometry data"""
    if self.marker_location is not None:
        return to_shape(self.marker_location).x
    return None
\end{mycode}

Việc hiện thực này cho phép hệ thống thực hiện các truy vấn không gian phức tạp như tìm kiếm các hoạt động trong bán kính nhất định xung quanh người dùng với hiệu năng tối ưu.

\subsection{Hệ thống tìm kiếm ngữ nghĩa và Trợ lý AI (RAG)}
Đây là tính năng thông minh của dự án, cho phép người dùng hỏi đáp về các hoạt động ngoại khóa, sự kiện và nhận gợi ý phù hợp với sở thích cá nhân. Hệ thống thực hiện quy trình RAG qua các bước:
\begin{enumerate}[leftmargin=*]
    \item \textbf{Vector hóa:} Sử dụng mô hình Embedding để chuyển đổi nội dung tiêu đề, mô tả và đặc điểm sự kiện thành các Vector 768 chiều.
    \item \textbf{Lưu trữ:} Sử dụng tiện ích \textit{pgvector} trong PostgreSQL để lưu trữ các vector embedding. Với quy mô dữ liệu học đường hiện tại, hệ thống thực hiện tìm kiếm chính xác Exact Nearest Neighbor; đồng thời kiến trúc sẵn sàng cấu hình chỉ mục xấp xỉ HNSW khi quy mô dữ liệu mở rộng.
    \item \textbf{Truy xuất:} Sử dụng toán tử khoảng cách Cosine (\textit{Cosine Similarity}) để tìm kiếm các sự kiện có ngữ nghĩa gần nhất với câu hỏi hoặc sở thích của người dùng.
\end{enumerate}

\begin{mycode}[Vector Similarity Search Query for Activities]{SQL}
-- Find the top 5 activities with similarity > 0.7
-- The <=> operator calculates Cosine Distance
-- Subtract from 1 to obtain Cosine Similarity
SELECT 
    title, description, meeting_location,
    1 - (embedding <=> '[vector_query]') AS similarity
FROM activities
WHERE is_deleted = false AND 1 - (embedding <=> '[vector_query]') > 0.7
ORDER BY similarity DESC 
LIMIT 5;
\end{mycode}

\subsection{Hiện thực Điểm danh Chống gian lận (Mã QR xoay động HMAC \& GPS Geofencing)}

Hệ thống hiện thực cơ chế điểm danh chống gian lận đa tầng:
\begin{itemize}[leftmargin=*]
    \item \textbf{Mã QR xoay động 30 giây (HMAC-SHA256):} Máy chủ tạo token điểm danh dựa trên thuật toán HMAC-SHA256 kết hợp timestamp làm tròn chu kỳ 30 giây và secret key của sự kiện. Mã QR và chuỗi ký tự OTP tự động đổi mới mỗi 30 giây trên màn hình ban tổ chức. Khi người dùng quét mã, máy chủ kiểm tra tính hợp lệ của token trong cửa sổ thời gian trôi (time window drift $\le 1$) để chấp nhận độ trễ mạng hợp lý.
    \item \textbf{Đối soát Hàng rào địa lý GPS Geofencing:} Khi gửi mã xác nhận, máy khách tự động kích hoạt tiến trình quét định vị vệ tinh GPS và gửi kèm tọa độ kinh độ, vĩ độ cùng độ chính xác phần cứng ($accuracy$). Máy chủ tính toán khoảng cách Haversine giữa tọa độ người dùng với tọa độ sự kiện, từ chối điểm danh nếu khoảng cách vượt quá bán kính quy định ($check\_in\_radius$, mặc định 100m--300m) hoặc sai số thiết bị quá cao ($accuracy > 100$m).
\end{itemize}

\subsection{Hiện thực Phân hệ Trợ lý AI và Hội thoại Thông minh (ReAct Agent)}

Phân hệ trợ lý học đường AI được hiện thực hóa thông qua giao diện lập trình RESTful API kết hợp mô hình đại lý suy luận tự động (ReAct Agent Pattern) và kiểm soát tần suất truy vấn (Rate Limiter):
\begin{itemize}[leftmargin=*]
    \item Tiếp nhận và xác thực yêu cầu hội thoại thông qua Access Token JWT, duy trì ngữ cảnh phiên hỏi đáp (Conversation History) từ phía Client.
    \item Tích hợp bộ lọc tần suất (Rate Limiter) tại tầng ứng dụng (Application Layer) nhằm kiểm soát số lượng yêu cầu theo địa chỉ IP/Token trong một khung thời gian xác định, bảo vệ tài nguyên tính toán và hạn ngạch gọi Gemini API.
    \item Điều phối vòng lặp suy luận ReAct: Khi câu hỏi yêu cầu dữ liệu thực tế, mô hình tự động phát tín hiệu gọi Tool (Tool Calling) để thực thi truy vấn vector tương đồng trên bảng \texttt{activities} qua tiện ích mở rộng \texttt{pgvector}, sau đó tổng hợp ngữ cảnh sự kiện để trả lời tự nhiên định dạng Markdown.
\end{itemize}

\subsection{Authentication}

Hệ thống triển khai cơ chế xác thực dựa trên tiêu chuẩn JSON Web Token (JWT). Mật khẩu người dùng được mã hóa bằng thuật toán bcrypt nhằm đảm bảo an toàn dữ liệu. Khi đăng nhập thành công, hệ thống cấp một mã định danh (Access Token) để người dùng thực hiện các yêu cầu tiếp theo thông qua lớp trung gian (Middleware).

\begin{mycode}[JWT and Password Security]{Python}
from jose import jwt
from passlib.context import CryptContext
from datetime import datetime, timedelta

pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")
SECRET_KEY = "your_secret_key"
ALGORITHM = "HS256"

def create_access_token(data: dict):
    to_encode = data.copy()
    expire = datetime.utcnow() + timedelta(minutes=30)
    to_encode.update({"exp": expire})
    return jwt.encode(to_encode, SECRET_KEY, algorithm=ALGORITHM)

def get_password_hash(password):
    return pwd_context.hash(password)
\end{mycode}

\subsection{Interactive API Documentation (Swagger UI)}

Một trong những ưu điểm cốt lõi của việc sử dụng FastAPI là khả năng tự động khởi tạo tài liệu API tương tác thông qua Swagger UI. Điều này giúp các nhà phát triển (đặc biệt là đội ngũ Frontend) dễ dàng theo dõi và thử nghiệm API mà không cần truy cập trực tiếp vào mã nguồn.

\begin{itemize}[leftmargin=*]
\item \textbf{Khám phá Điểm cuối (Endpoints):} Tất cả các đường dẫn (routes) được định nghĩa trong các router module đều được chỉ mục hóa tự động.
\item \textbf{Kiểm soát dữ liệu đầu vào:} Giao diện hiển thị rõ ràng các lược đồ dữ liệu (Schemas) cần thiết cho mỗi yêu cầu, giúp giảm thiểu lỗi định dạng dữ liệu khi trao đổi giữa Client và Server.
\item \textbf{Thử nghiệm trực tiếp:} Cho phép thực hiện các yêu cầu HTTP (GET, POST, PUT, DELETE) trực tiếp trên trình duyệt để kiểm tra logic xử lý của Backend ngay lập tức.
\end{itemize}

\subsection{Đóng gói ứng dụng với Docker trong môi trường sản xuất}

Để đảm bảo hệ thống vận hành ổn định và độc lập trên môi trường sản xuất, dự án được đóng gói thành các container Docker riêng biệt. Toàn bộ kiến trúc phân tầng bao gồm Nginx Reverse Proxy (phục vụ SPA tĩnh và ủy quyền chuyển tiếp), máy chủ FastAPI Backend và cơ sở dữ liệu PostgreSQL (tích hợp PostGIS/pgvector) được điều phối thông qua tệp cấu hình \texttt{docker-compose.prod.yml}:

\begin{mycode}[Production Docker-Compose Stack]{yaml}
services:
  # 1. PostgreSQL Database (PostGIS & pgvector extensions)
  db:
    build: { context: ., dockerfile: Dockerfile.db }
    environment:
      POSTGRES_USER: ${POSTGRES_USER:-uniconnect}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: ${POSTGRES_DB:-uniconnect}
    volumes:
      - postgres_prod_data:/var/lib/postgresql/data
    restart: unless-stopped

  # 2. FastAPI Backend Application Server (Isolated Internal Network)
  server:
    build: { context: ./server, dockerfile: Dockerfile.prod }
    env_file: .env
    environment:
      APP_ENV: production
      DATABASE_URL: postgresql+asyncpg://...
      TRUSTED_PROXY_IPS: "127.0.0.1,172.16.0.0/12"
    depends_on:
      db: { condition: service_healthy }
    restart: unless-stopped

  # 3. Nginx Ingress Reverse Proxy & Static SPA (Public Port 80)
  client:
    build: { context: ./client, dockerfile: Dockerfile.prod }
    ports: ["80:80"]
    depends_on:
      server: { condition: service_healthy }
    restart: unless-stopped

volumes:
  postgres_prod_data:
\end{mycode}

Kiến trúc triển khai phân tách rõ ràng ranh giới mạng: dịch vụ Nginx đóng vai trò là điểm đón tiếp duy nhất (Ingress) mở cổng ra bên ngoài, trong khi máy chủ Backend và Cơ sở dữ liệu hoạt động hoàn toàn bên trong mạng nội bộ cô lập của Docker, gia tăng mức độ an toàn thông tin cho toàn bộ hệ thống.
